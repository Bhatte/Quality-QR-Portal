# Configure authentication in Azure App Service by using a configuration file
  * 02/02/2022


Feedback
##  In this article
  1. [Enable file-based configuration](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-file-based#enable-file-based-configuration)
  2. [Configuration file reference](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-file-based#configuration-file-reference)
  3. [Related content](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-file-based#related-content)


With [App Service authentication](https://learn.microsoft.com/en-us/azure/app-service/overview-authentication-authorization), the authentication settings can be configured with a file. You may need to use file-based configuration to use certain preview capabilities of App Service authentication / authorization before they're exposed via [Azure Resource Manager](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/overview) APIs.
Remember that your app payload, and therefore this file, may move between environments, as with [slots](https://learn.microsoft.com/en-us/azure/app-service/deploy-staging-slots). It is likely you would want a different app registration pinned to each slot, and in these cases, you should continue to use the standard configuration method instead of using the configuration file.
[](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-file-based#enable-file-based-configuration)
## Enable file-based configuration
  1. Create a new JSON file for your configuration at the root of your project (deployed to C:\home\site\wwwroot in your web / function app). Fill in your desired configuration according to the [file-based configuration reference](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-file-based#configuration-file-reference). If modifying an existing Azure Resource Manager configuration, make sure to translate the properties captured in the `authsettings` collection into your configuration file.
  2. Modify the existing configuration, which is captured in the [Azure Resource Manager](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/overview) APIs under `Microsoft.Web/sites/<siteName>/config/authsettingsV2`. To modify it, you can use an [Azure Resource Manager template](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview) or a tool like [Azure Resource Explorer](https://resources.azure.com/). Within the authsettingsV2 collection, set two properties (you may remove others):
    1. Set `platform.enabled` to "true"
    2. Set `platform.configFilePath` to the name of the file (for example, "auth.json")


The format for `platform.configFilePath` varies between platforms. On Windows, both relative and absolute paths are supported. Relative is recommended. For Linux, only absolute paths are supported currently, so the value of the setting should be "/home/site/wwwroot/auth.json" or similar.
Once you have made this configuration update, the contents of the file will be used to define the behavior of App Service Authentication / Authorization for that site. If you ever wish to return to Azure Resource Manager configuration, you can do so by removing changing the setting `platform.configFilePath` to null.
[](https://learn.microsoft.com/en-us/azure/app-service/configure-authentication-file-based#configuration-file-reference)
## Configuration file reference
Any secrets that will be referenced from your configuration file must be stored as [application settings](https://learn.microsoft.com/en-us/azure/app-service/configure-common#configure-app-settings). You may name the settings anything you wish. Just make sure that the references from the configuration file use the same keys.
The following exhausts possible configuration options within the file:
